# 数治通三期产品设计：服务应用

> 文档版本：v1.0 ｜ 2026-10-07 ｜ 对应用户规格"第三阶段：服务应用"与模块 5/8/9
> 前置：一期（治理基础）、二期（治理执行）已完成；本期在其之上构建统一服务与应用层。

---

## 1. 目标与验收

**一句话**：把一、二期的治理成果（目录、标准、主数据、认责、质量规则）封装成可复用的数据服务，用统一口径的指标支撑分析，让用户通过智能问数直接消费。

**验收标准**（用户规格原文）：
- 常用分析使用统一口径 —— 指标计算引擎按指标定义的版本化口径执行，问数优先调用已验证指标/服务；
- 数据来源和权限可验证 —— 每个回答/服务调用记录来源、标准版本、责任人；行级部门过滤 + 服务授权双重校验。

## 2. 统一数据服务（规格模块 8）

### 2.1 服务目录
六类服务全覆盖：主数据服务 / 关系服务 / 明细查询服务 / 指标服务 / 组合分析服务 / 校验服务。
每个服务绑定：数据来源、标准版本、责任人、权限要求（公开/授权）、质量状态、更新频率、接口版本。

### 2.2 生命周期
申请 → 授权（admin 审核） → 发布（写版本+通知） → 下架。
下架做依赖检查：存在"已授权订阅"或"近 30 天调用"时拒绝并返回依赖清单（复用一期目录下架模式）。

### 2.3 运行态
- 限流：每用户每服务每分钟 N 次（`SZT_SVC_RATE_LIMIT`，默认 60），内存令牌桶，超限 429；
- 调用日志：每次调用记服务、用户、耗时、状态码、错误（`service_calls`），失败调用计入错误率；
- 变更通知：发布/版本变更写 `service_notices`，订阅方可查看。

### 2.4 种子服务（真实可调）
| 编码 | 名称 | 类型 | 权限 |
|---|---|---|---|
| SVC-MD-EQ | 设备主数据查询服务 | 主数据服务 | 公开 |
| SVC-REL-3CODE | 设备三码关系查询服务 | 关系服务 | 公开 |
| SVC-WO-DETAIL | 维修工单明细查询服务 | 明细查询服务 | 授权 |
| SVC-MAT-COST | 备件消耗组合分析服务 | 组合分析服务 | 授权 |
| SVC-CODE-VALIDATE | 数据标准值域校验服务 | 校验服务 | 公开 |

执行引擎 `app/services_engine.py`：`invoke_service(conn, code, params, user)` —— 404/未发布检查 → 限流 → 权限（super_admin/admin 直通；公开直通；否则需已授权订阅）→ handler 计时执行 → 写调用日志。

## 3. 指标标准管理与计算（规格模块 5）

### 3.1 指标定义
字段：编码、名称、业务定义、计算规则（分子 SQL/分母 SQL/说明）、纳入/排除范围、时间规则（发生时间/完成时间/统计时点）、数据粒度、分析维度（name→expr）、数据来源、责任部门/角色、版本、状态。

### 3.2 版本管理
- 更新定义 → 版本号 minor+1，旧定义快照存 `indicator_versions`，历史结果保留旧版本；
- `compare?from=&to=` 逐项比对口径字段，`has_caliber_diff` 为真时前端告警；
- 缓存键含部门范围（`md5(code|version|period|dimension|dimension_value|dept_scope)`），杜绝跨部门缓存串扰。

### 3.3 计算引擎
`app/metrics_engine.py::compute_metric`：模板占位符（`{period_start}`/`{period_end}`/`{dept_filter}`/`{dimension_filter}`）→ SELECT-only 安全校验（注释剥离、单语句、危险词黑名单、FROM/JOIN 表白名单）→ 执行分子/分母 → value=numerator/denominator → 写 `indicator_results` 缓存。

### 3.4 种子指标（真实可算）
| 编码 | 名称 | 口径要点 | 版本 |
|---|---|---|---|
| WO_ON_TIME_RATE | 维修工单按期完成率 | v1：实际≤计划；v2：延期审批通过也算按期 | v1.0→v2.0（口径差异已验证：19/22 vs 20/22） |
| EQ_INTACT_RATE | 设备完好率 | 当期无维修工单的在册设备占比 | v1.0 |
| MAT_COST_BY_MODEL | 备件消耗金额（按型号） | v1：全部领料；v2：剔除退料 | v1.0→v2.0（60900 vs 58000 差异已验证） |

### 3.5 试点数据
`work_orders` 26 行（P-AFW-001A/001B，AFW-1000，一号基地为主；2 行二号基地；2 行维修处；含超期/延期审批/取消/进行中），`material_issues` 44 行（含 2 行负金额退料），日期覆盖 2025-11~2026-10。

## 4. 智能问数（规格模块 9）

### 4.1 问答流程
中文提问 → 意图识别（metric/service/sql/refuse）→ 实体提取（时间/型号/基地/逻辑编码）→ 缺失条件澄清（metric 缺时间、校验缺标准编码时追问）→ 权限校验 → 优先调用已验证指标/服务 → 五要素回答。

### 4.2 回答五要素
1. 问题理解（意图 tag + 实体 chips + 一句话）；
2. 统计口径 + 时间 + 组织范围（口径取自指标 `biz_def`/`time_rule`，永不来自 LLM）；
3. 数据结论与图表（自动选型：趋势→line、对比→bar、占比→pie、单值→stat）；
4. 来源 + 更新时间 + 质量提示（取消单排除数等）；
5. 可继续追问的方向（chips，点击再问）。

### 4.3 受控查询与红线
- 授权语义模型内受控查询：`QA_TABLES = {work_orders, material_issues, device_links}` 白名单；SELECT-only 校验（注释剥离、禁分号、危险词黑名单、表名提取）；行级部门过滤（`{dept_filter}`，JOIN 场景支持别名前缀）；
- LLM 接入统一 `LLMClient`（`SZT_LLM_PROVIDER` 可配，默认 disabled 降级）：仅用于 SQL 生成候选（仍强制校验）与结论润色（数字丢失回退）；
- 红线：模型不得自行定义企业指标口径；未经验证的推测不得写成事实；口径外问题明确拒绝并引导；问数历史/收藏沿用 askdata 模式，每次问数写审计。

## 6. 页面
- 服务中心 `/services`：服务目录（类型筛选/详情抽屉/调用测试）、我的申请、调用监测（admin）；
- 指标中心 `/metrics`：指标卡片、口径说明、趋势图、版本对比（口径差异告警）、指标计算；
- 智能问数 `/qa`：对话、五要素回答卡、历史/收藏、澄清追问 chips。

## 7. 已知局限
- 限流桶为进程内存，多 worker 部署下按进程隔离；
- LLM 默认 disabled，真实 Key 联调未做；
- 问数 SQL 意图的型号/基地/时间实体暂未作为明细过滤条件（仅部门过滤），已预留 `entity_filter_clause` 接入点；
- docker compose 未实际 build 验证（本机无 docker）。
