# 数治通四期产品设计：推广运营

> 文档版本：v1.2 ｜ 2026-10-07 ｜ 对应平台版本 v1.2.0
> 依据：用户《数治通》规格"第四阶段：推广运营"、模块 10（平台运营与审计）、章节七（权限与变更控制）。

---

## 1. 建设目标与验收标准

**目标**：把一期（治理基础）、二期（治理执行）、三期（服务应用）沉淀的治理资产推广到多基地，形成"共性标准统一维护、基地差异受控管理"的机制；让每一次变更都可分析、可确认、可通知、可回退；让运营情况可度量。

**验收标准**：形成共性标准与基地差异管理机制，服务持续复用。

## 2. 功能模块

### 2.1 多基地配置（`/bases`）

- **基地档案**：编码 / 名称 / 堆型 / 状态 / 说明。种子数据：BASE-A（基地A，PWR1000，运行中）、BASE-B（基地B，PWR600，建设中）。
- **两层治理**：
  - 共性层：集团统一维护的标准 / 指标（`standards` / `indicators` 表，状态"已发布"）。
  - 差异层：`std_base_diff` / `indicator_base_diff` 登记基地差异（差异类型、差异内容 JSON、差异原因、生效起止、状态草稿/已发布）。
- **差异示例**（种子）：STD-001「设备核安全分级」在 BASE-B 的允许值为 `["NS1","NS2","非核级"]`（B基地堆型不涉及NS3级设备）；WO_ON_TIME_RATE 在 BASE-B 的统计范围扩大至建设期工单。
- **有效口径查询**：`GET /bases/effective/standard/{id}?base_code=` 返回合并差异后的允许值 + 口径声明文本；`GET /bases/effective/indicator/{code}?base_code=` 同理。
- **问数集成**：`/qa/ask` 支持 `base_code` 参数；指标问数自动选用基地差异口径，并在回答的"口径与范围"区声明所用口径版本，结论末尾追加【口径声明】。智能问数页顶部有基地选择器（默认"集团共性口径"）。

### 2.2 变更中心（`/changes`）

变更类型：标准版本 / 指标口径 / 服务接口 / 主数据模型。

**状态机**：

```
草稿 →(提交)→ 影响分析中 →(自动)→ 待确认 →(全部确认)→(生效)→ 已生效 →(回退)→ 已回退
                                    ↘(驳回)→ 已驳回
```

**自动影响分析**（提交时触发，按变更类型生成）：

| 变更类型 | 分析出的影响类别 |
|---|---|
| 标准版本 | 字段映射、质量规则、落标检查、数据目录、数据服务、责任人 |
| 指标口径 | 数据服务（全部指标类服务）、责任人 |
| 服务接口 | 调用方（已授权订阅）、责任人 |
| 主数据模型 | 字段映射、分发目标、责任人 |

每项影响含：类别、受影响资产、需采取的行动。责任人自动解析：资产 owner 文字 → 同名用户 → 同部门 admin/operator → 兜底 admin（注明"默认确认人"），去重后生成确认项。

**控制规则**：生效时若存在"待确认"项，返回 400 并在错误信息中列出缺失确认清单，阻止生效。

**生效**：写入版本（标准→`std_versions`、指标→`indicator_versions`、服务→`service_versions`、主数据模型→`md_models.version`）+ 生效时间；生成站内通知（责任人 / 申请人 / 服务调用方）记入 `change_notices`。

**回退**：用创建时保存的目标行快照恢复，状态→已回退，并通知申请人。仅"已生效"可回退。

### 2.3 运营评价（`/ops` + 仪表盘升级）

- `GET /ops/overview`：治理进展（对象/已发布资源/已发布标准/主数据/指标/服务/基地数）、质量趋势（近 N 天检出/关闭/未关闭，N=`SZT_OPS_TREND_DAYS` 默认 14）、服务使用 Top5（调用量/错误率）、问数使用（总次数/口径命中率/按天趋势）、变更统计（按状态/已发通知数）。
- `GET /ops/audit-trend`：审计日志按天/动作聚合（admin）。
- 首页仪表盘升级为运营中心视图：保留原 5 张统计卡 + 待审批事项，新增"运营评价"卡片（质量趋势 / 服务 Top5 / 变更统计三栏）。

## 3. 权限矩阵（新增）

| 操作 | 最低角色 |
|---|---|
| 基地/差异查看、运营大盘查看 | operator |
| 基地创建、差异登记、变更申请/提交 | operator |
| 差异发布、变更确认（代确认）/生效/驳回/回退 | admin |
| 审计趋势 | admin |

## 4. 配置项（新增）

| 变量 | 默认 | 说明 |
|---|---|---|
| `SZT_OPS_TREND_DAYS` | 14 | 运营大盘趋势统计天数 |

其余配置沿用 `.env.example`（服务器 / 数据库 / 大模型 / 限流等）。

## 5. 数据模型（新增表）

`bases`（基地档案）、`std_base_diff`（标准基地差异）、`indicator_base_diff`（指标基地差异）、`change_requests`（变更申请）、`change_impacts`（影响明细）、`change_confirmations`（责任人确认）、`change_notices`（变更通知）。

## 6. 验收用例

1. 在 BASE-B 查看 STD-001 有效口径：允许值为 NS1/NS2/非核级，且有口径声明。
2. 智能问数选"基地B"提问"近一年维修工单按期完成率是多少"：回答含【口径声明】基地B差异。
3. 新建"STD-001 升级 v1.1"变更 → 提交 → 看到 8 项影响与确认人 → 直接点"生效"被 400 拦截并列出缺失确认 → 确认 → 生效（标准版本变为 v1.1，通知 2 条）→ 回退（版本恢复 v1.0）。
4. 首页运营评价卡片有数据；`/ops/overview` 返回完整结构。
