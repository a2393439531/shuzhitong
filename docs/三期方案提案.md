# 数治通三期方案提案：数据应用工作台

> 状态：待用户拍板。拍板后按此开工。
> 依据：用户四期规划（一期治理基础 ✓ / 二期治理执行 ✓ / 三期数据应用 / 四期价值度量）；askdata v1.0 已发布（GitHub `a2393439531/askdata`）。

## 1. 本期一句话

把前两期"管起来"的数据变成"用起来"的入口：**统一数据服务 + 指标计算 + askdata 智能问数**，形成"数据应用工作台"。

## 2. 范围（三个模块）

### 模块 A：统一数据服务
- 对前两期沉淀的治理资产（业务对象、数据目录、数据标准、主数据、质量结果）提供统一只读 API 层。
- 权限沿用现有四角色体系；所有调用进审计日志。

### 模块 B：指标计算
- 指标定义（名称、口径、计算逻辑、数据来源、负责人）+ 版本管理。
- 指标发布走现有审批中心（提交→技术核验→归口审核→发布），与目录/标准同链路。
- 试点口径先行：设备完好率、维修工单及时率、备件周转（核电设备—维修工单—备件链路）。

### 模块 C：askdata 智能问数集成（核心）
- 把 askdata v1.0（模块九智能问数 + 模块十审计/模板/历史）作为工作台的问数引擎接入。
- **关键集成点**：askdata 的 schema 上下文不再手写，改由数治通的**数据资源目录 + 数据标准**自动供给——问数只能问到"已治理、已发布"的数据，这是问数产品和治理平台合体的真正价值。
- 质量规则作为护栏：问数结果可关联质量检出（如"该表近 7 天有 3 条质量问题"提示）。
- 前端按用户偏好做**紧凑排版**（对照参考风格，不留大面积空白）。

## 3. 为什么现在是合适的时机

1. askdata v1.0 已是可用种子（联调 15/15、pytest 12/12），无需重写，直接复用。
2. 一、二期已把 schema 的"官方来源"建好（目录 + 标准 + 认责），集成是顺水推舟。
3. 问数小模型新结论（796 样本打平 2.4 万，"见过每张表"比堆量重要）意味着：给每张治理表配少量示例即可，不需要重训练或大规模标注——这条结论已在待推送队列里。

## 4. 验收标准

- pytest 全过（目标 80+，以前两期 24/24、61/61 为基准）。
- 演示链路：中文提问"辅助给水泵今年维修了几次、用了哪些备件"→ 生成 SQL → 图表 + 解读，SQL 只触及已发布治理表。
- 指标发布全链路走通（定义→审批→发布→问数可引用）。
- 全走 `.env` 可配置（延续二期约定）。

## 5. 明确不做（留给四期）

- 数据资产价值评估、KPI 看板（四期）。
- 多租户、外部 SSO。
